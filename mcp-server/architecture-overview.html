Figma MCP Bridge

Figma 插件把当前选区同步到本地 MCP Server；Agent 通过 MCP tools/resources/prompts 读取 summary、按需懒加载节点 detail，并用于设计还原、审查和设计系统提取。

整体链路

Figma Plugin Panel

打开 Open AI Agent Bridge 后保持 heartbeat。选区变化自动推 summary；收到懒加载请求后，按 nodeId 导出该节点 subtree detail。

->

Local MCP Server

监听 localhost:7800，缓存 summary/selection/diff/node-detail，并维护 pending node-detail request 队列。

->

AI Coding Agent

通过 MCP stdio 调用 tools。常规流程是读取 summary，搜索目标节点，再调用 get_design_node 自动触发 detail 懒加载。

谁启动 MCP Server

Agent 启动

Codex/Claude/Cursor 根据 MCP 配置启动：

node mcp-server/dist/index.js

插件只负责推送

Figma 插件不能管理 MCP stdio 进程。它只通过 HTTP 调用本地 server endpoint，并展示连接/同步状态。

HTTP Endpoints

Endpoint方向用途
/api/heartbeatUI -> Server每 15 秒刷新连接状态。
/api/push/summaryUI -> Server选区变化后自动推轻量 summary。
/api/push/selectionUI -> Server手动 AI Detail 导出时推完整选区 detail。
/api/push/diffUI -> Server手动 AI Diff 导出时推 diff。
/api/requestsUI <- ServerUI 每秒轮询 pending node-detail requests。
/api/push/node-detailUI -> Server插件完成懒加载后推目标节点 subtree detail 或错误。

Lazy Detail Flow

  1. Agent 调 get_design_summary 或 search_nodes 找到目标 nodeId。
  2. Agent 调 get_design_node({ nodeId })。
  3. 如果 server 只有 summary 且插件在线，server 创建 pending node-detail request 并等待最多 10 秒。
  4. UI 轮询 /api/requests，发现请求后发 mcp-detail-request 给插件 runtime。
  5. 插件用 figma.getNodeByIdAsync(nodeId) 找节点，序列化完整 subtree detail。
  6. UI 推 /api/push/node-detail，server 唤醒 tool 并返回 source: "node-detail"。

MCP Tools

Status

get_connection_status 返回 connected、hasSummary、hasSelection、hasDiff、hasNodeDetails、pendingDetailCount。

Structure

get_design_summary 读取轻量节点树。

Node Detail

get_design_node 优先读 full detail，其次读 lazy node detail，最后从 summary 触发懒加载。

Search

search_nodes 只搜索 summary/detail，不批量触发懒加载。

Tokens

get_design_tokens 从完整 detail 或 summary 中读取 tokens。

Diff

get_design_diff 读取手动同步的 diff。

Agent 推荐流程

  1. 先调用 get_connection_status，确认插件在线且 summary 新鲜。
  2. 调用 get_design_summary 理解选区结构。
  3. 用 search_nodes 找目标区域。
  4. 调用 get_design_node({ nodeId }) 自动获取该节点 subtree detail。
  5. 需要整组选区上下文时，再使用手动 AI Detail 同步后的 get_design_selection。
