Figma MCP Bridge

这个桥接方案让 Figma 插件把当前选区推送到本地 Node MCP Server，再由 Claude Code、Cursor、Codex 等 Agent 通过标准 MCP tools/resources/prompts 读取设计数据。

整体链路

Figma Plugin Panel

打开 Open Export Panel (MCP Debug) 后，插件保持 heartbeat，选区变化自动推 summary；手动导出 detail/diff 时同步推送。

→

Local MCP Server

HTTP 监听 localhost:7800 接收插件数据，写入按 fileKey + pageId + sessionId 隔离的内存缓存。

→

AI Coding Agent

Agent 通过 MCP stdio 自动启动 server，调用 tools、读取 resources 或使用 prompts 获取设计上下文。

谁启动 MCP Server

Agent 启动

Claude Code、Cursor、Codex 等 Agent 根据仓库根目录的 .mcp.json 启动：

node mcp-server/dist/index.js

插件不启动 Server

Figma 插件只负责向本地 HTTP 端点推送数据。插件无法管理 Agent 侧 MCP stdio 进程。

插件推送规则

动作 HTTP Endpoint 说明
打开面板 / 每 15 秒 /api/heartbeat 让 Agent 判断插件是否在线。
选区变化 /api/push/summary 自动推轻量结构，避免大选区卡住 Figma。
手动导出 AI Detail /api/push/selection 同步完整 AI detail，供 Agent 查节点、tokens、组件。
手动导出 AI Diff /api/push/diff 同步增量变化，供 Agent 做修改验证。

MCP Tools

状态

get_connection_status 查看 connected、lastPushAt、hasSummary、hasSelection、hasDiff。

结构

get_design_summary、get_design_selection、get_design_node 读取树和节点详情。

查询

search_nodes 按 id、名称、类型、文本、componentId、hint 搜索节点。

变化

get_design_diff 读取手动推送的 AI Diff。

设计系统

get_design_tokens 读取 colors、typography、spacing。

组件

get_component_definitions 读取组件定义或指定 componentId。

MCP Resources 和 Prompts

Resources

figma://status、figma://summary、figma://selection、figma://diff、figma://tokens、figma://components

Prompts

implement-design、review-design、extract-design-system 用于引导 Agent 按正确顺序读取设计数据。

Agent 推荐使用流程

  1. 调用 get_connection_status，确认插件在线且数据新鲜。
  2. 调用 get_design_summary 理解选区结构。
  3. 用 search_nodes 或 get_design_node 精确读取目标节点。
  4. 需要完整实现时，让用户在面板手动导出 AI Detail，再读取 selection、tokens、components。
  5. 需要增量验证时，让用户手动导出 AI Diff，再调用 get_design_diff。
